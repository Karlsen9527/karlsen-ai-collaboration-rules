# 工程协作任务上下文空模板

适用标准：[工程协作标准 1.0.0](../standards/AGENT_COLLABORATION.md)。发布状态与可信批准按该标准独立清单核验；模板不产生授权。复制到本任务获准空间填写，不把私人实例、审批原文、身份信息或本地敏感路径提交到共享规范仓库。本模板为人工可读 Markdown，不自称已经实现机器 schema、验签或调度接口。

简单任务可压缩为单条记录，只保留适用字段和必要引用；不适用项说明原因。模板不要求每轮重写稳定信息，也不要求把全部测试、配置或发布流程附加给短小任务。

本模板仅供已明确采用工程协作标准的工程任务；普通对话不要求建立这些字段。任务正文先冻结，再机器计算正文原始字节哈希、取得精确批准，最后由外置派发/批准记录登记实际批准和任务提交定位。正文冻结后不填入自身哈希、包含自身的 task_commit 或实际批准状态；正文只预先给出这些外置记录的获准位置。任务快照一经批准便不可覆盖或回填。下文“实际结果、run_id、当前状态、result_commit”等运行后字段，在批准快照中只定义记录位置和要求；实际运行事实写入获准报告、交付回执或后续记录，不回填已批准任务。当前状态由其唯一责任方写入独立权威位置。

- 当前模式：<方案模式 / 执行模式>

- 当前任务目标：<可验收结果>
- 非目标：<本次不做的产品或流程范围>
- 本轮动作与产物：<具体清单>

## 3 适用规范与来源

每份规范单独填写，不用一个仓库版本笼统代替：

- 标识 / 正式版本：<已正式采用的版本；候选不能冒充>
- 来源仓库 / 精确 commit / 相对路径：<能取回>
- 原始字节 expected_sha256：<可信材料给定值>
- computed_sha256 / 字节数 / 核验时间：<实际机器结果>
- 发布与批准证据引用：<可在可信渠道核对；不复制私人原文>
- 规范可用性：<已验证适用 / 最后核验缓存未证明最新 / 无法核验>
- 项目例外及其批准引用：<没有则写无；不得降低上位安全要求>

## 4 四类定位分开

- 任务定位回执位置：<预先指定的外置派发/批准记录位置；实际 task_commit、任务仓库与路径在任务提交形成后由该记录登记，不填入本正文>
- work_base：<实际工作仓库 + commit；非 Git 则登记获准文件快照>
- 额外执行输入：<与运行相关的未提交差异、未跟踪文件和外部输入；无则写无>
- current_goal：<当前目标状态的权威位置与已读时点>
- 结果定位回执位置：<外置交付回执位置；实际 result_commit 在结果提交形成后由该回执登记，不填入本正文>
- 输入哈希范围：<原始字节逐文件列表或已定义的包算法>
- 输入排除：<秘密、私人日志、未授权数据等；不能排除实际依赖后仍声称完整基线>

## 5 环境 允许动作和禁止动作

- 目标环境：<用户选定环境或已获准环境；本地绝对路径保留在本地映射>
- 允许读取：<仓库/相对路径/外部来源与用途>
- 允许修改：<明确相对路径或有界集合>
- 允许执行：<实现、测试、重试等具体动作与边界>
- 允许外部写入：<提交、推送、PR、报告上传等逐项；不涉及写无>
- 允许外部接收方与数据范围：<适用时填写>
- 不允许动作或文件：<具体约束>
- 费用、用量、重试或时间边界：<已批准上限；无法获知的指标明确写未知>
- 等待与观察策略：<所等结果、已授权读取范围、停止目标、可用机制；无则写无>
- 不允许的额外基础设施：<例如本任务不部署轮询器或守护进程>

## 6 可信批准要求与外置记录

- 外置派发/批准记录位置：<预先确定的获准位置或可信渠道；此正文只引用位置>
- 申请批准的动作、产物、对象、验收及有界重试：<完整的拟批准范围，不预填已批准>
- 批准绑定要求：外置记录必须关联本 task_id / revision、冻结正文的原始字节 SHA-256、获准范围和可核对的真实用户批准。
- 接单核对要求：执行方实际读取外置记录并核对身份、范围、正文哈希与权限；缺失则等待，不靠正文自证批准。
- 外置记录实际字段：批准状态、可信身份引用、批准证据定位、批准时点、正文 expected/computed 哈希及核验信息；任务提交产生后登记 task_commit、仓库与路径。后续变化以获准追加记录保存，不回填本正文。
- 无自引用要求：外置记录中的任务哈希仅针对冻结任务正文原始字节，明确排除外置记录自身；外置记录也不预填包含自身的未来 commit 或自身最终哈希。
- 私人批准原文与身份资料：只保留在获准可信渠道；共享位置仅使用可核对且适合共享的引用。

- 当前任务完成条件：<可验证终点>
- 流程验收范围：<适用环节；不涉及写不适用>
- 产品完成条件：<另行产品规格；本任务不验收整个产品时明确>
- 历史事件证据：<有则定位；缺失写 UNVERIFIED，不重构私人日志>

## 10 本轮确认菜单

仅在展示阶段方案或流程时填写本节，普通问答与纯澄清不附加。

当前方案版本：<明确版本>；执行范围：<具体动作>；产物：<具体列表>。

1. 确认执行：仅批准上面列出的本轮范围、产物及版本。
2. 重新检查：集中检查并交付完整修订。
3. 确认流程：展示或核对主业务流程，不代表批准执行。

有问题时使用独立题号与 A/B/C 选项，推荐项首位并说明取舍；答案示例“1A”。裸数字“1”只在唯一明确待确认事项下解释为批准。存在多个待确认项时先澄清，不猜测。
