# Codex 偏好与接入说明

## 当前作用域

core 7.0.0 只用于用户与主助手，Codex 担任任务执行者时默认不加载、维护 core，不承担聊天菜单；按完整任务路线、项目明确约束及环境安全权限规则执行。下文模型偏好仅在获准配置任务中使用，有限批次及 goal 技术条款仅在明确选用该历史模式时适用。工程 1.1.0 及其 core 2.0.0 依赖仍按原固定快照读取，不被当前入口升级或解除；本次不改配置模板，不证明接入、旧绑定同步或在线能力完成。

主助手角色、公开读取与能力不足时的处理见 [统一接入说明](../README.md)；本适配不要求其他模型安装本客户端。

本文是 Codex 附属接入说明，随精确文件快照定位，不另设独立版本。读取本文或发布模板不会修改任何配置或权限；模板准备、配置写入与运行验证分别核验。

## 两行偏好模板

具体键值唯一维护在 [config.toml.example](config.toml.example)；该文件恰为两行，不在本说明另抄一份值。

该模板只表达本用户在 Codex 适配层的模型与推理强度偏好。没有审批、沙箱、网络或权限字段；不把“较高推理强度”解释为更宽权限，不改变其他模型的配置。

这些配置键与可用取值应以所用客户端版本及官方资料为准。这里的模型选择是用户偏好，不是对所有账号、所有客户端或所有时刻都可用的承诺。当前任务的模型和配置是否真正生效，需要运行环境证据；写出模型名称不等于完成切换。

## 采用前检查

1. 确认实际使用 Codex 的客户端、版本、账号可用模型和配置读取能力。
2. 核对用户希望采用的作用域：用户级或已信任项目级。先读取现有有效配置和覆盖来源，不覆盖未知设置。
3. 确认配置修改已在本次授权范围；规范材料的审阅或发布不含配置安装。一般设置写入和权限相关设置分别处理。
4. 若模板中的目标模型或推理强度在该环境不被支持，说明实际限制，等待用户选择，不静默降档后继续宣称按偏好运行。
5. 模型与高推理强度可能改变延迟、用量及费用。没有实际计量就写未知；需要变更偏好时说明质量、速度和成本取舍，不承诺未经验证的收益。

## 获准部署后的最小验证

- 只将两个所需键合入选定作用域的已有配置，不用整文件替换抹掉其他内容。
- 用户级常见位置为 ~/.codex/config.toml；项目级为 .codex/config.toml。是否读取项目配置、信任要求与优先级，应按实际客户端及官方文档确认。示例路径不代表已定位本机配置，也不要求所有机器采用同一路径。
- 核对启动参数、配置 profile、用户级与项目级等可能的覆盖来源，记录最终有效设置与验证方式。
- 在获准且成本可接受的实际任务中确认模型和推理设置；不从模板内容推断运行时状态。
- 明确记录：模板已准备 / 配置已写入 / 运行已验证，分别成立才分别报告。
- 仓库中的配置示例不自动同步到用户电脑，项目批准也不自动覆盖其他项目设置。

## 显式采用历史规范时的加载验证

仅在项目明确采用的历史工程标准要求读取其固定 core 依赖时，按该历史契约验证。AGENTS.md 等只放薄入口与固定引用，不复制 core；发现入口、读取固定规范、原始字节核验、可信批准引用、缓存与撤销处理须分别验证。模型配置可用，不能推出这些加载能力已经存在。

事件读取、任务执行、后台等待、报告读取和 24 小时服务能力分别验收。不因两行配置存在就宣称自动调度或全天工作已部署。

## 可选有限批次原生目标适配

只在项目明确采用工程正文第十二、十三节并完成本机预检时，将 `/goal 开始接单` 解释为一次冻结 Q0 的执行交付。共用规则仅引用工程正文，不在本适配复制。检查当前项目、原生入口和工具、公开状态及已有未完成目标；任务授权不自动处理旧目标。

源码依据固定为 [openai/codex 95ec4686 的 goal spec](https://github.com/openai/codex/blob/95ec468619386ebb93506ac2091a48e5a558d25c/codex-rs/ext/goal/src/spec.rs)：get_goal 读取当前线程目标，create_goal 创建，update_goal 使用 status（complete / blocked / paused）。complete 必须真实完成且无剩余必需工作；blocked 须同一障碍至少连续三轮且无法取得有意义进展；paused 需用户明确要求。本快照的 update_goal 不能恢复或修改预算。不要使用 DSH 的 goal_id/revision/action 参数。

实际安装版本与公开工具为本机核对对象；上述源码不是部署证明。确认终态工具后的工具调用边界，不能未经核对套用 DSH 终态禁调规则；未知时记录 UNVERIFIED 并暂停依赖动作。先完成获准交付及证据，再如实保留原生回执，按中央规则由用户交回协调者。预算或退出不能伪装 complete；没有自主暂停权时请求用户操作。不承诺全天续行、自动恢复或跨回合验证已经通过。
